### how this actually works

Every idea gets looked at from two directions before it becomes code, and again before that code becomes something someone else depends on. Not everything survives that. What does tends to hold up.

There's no process document for this. It happens in conversation, mostly disagreement, until one version is left standing.

<p align="center">– – –</p>

### where things stand

<p align="center"><kbd>idea</kbd> → <kbd><b>building</b></kbd> → <kbd>shipped</kbd> → <kbd>repeat</kbd></p>

We're in the build stage of the first project worth building. What it is doesn't appear here — it isn't ours to describe yet, and it may not stay the same shape by the time it's done.

<p align="center">– – –</p>

### what we're trying to hold onto

- finish the small thing before describing the big thing
- resolve disagreement before the code exists, not after it ships
- a private repository isn't an absence of progress
- this page is allowed to be wrong by next month — the work isn't
